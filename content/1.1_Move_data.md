# Moving data to AWS

To move your datasets and model weights from LUMI to an AWS S3 bucket, you first need to configure IAM credentials and then use a data transfer tool like `s3cmd`.

## AWS IAM Setup

To securely transfer your data from LUMI to AWS, you will need to create an Identity and Access Management (IAM%) user with the appropriate permissions and generate access keys.

### 1. Log in to the AWS Console
Navigate to [aws.amazon.com](https://aws.amazon.com/) and sign in. Use the search bar at the top to search for and open **IAM**.
   
### 2. Create a new IAM User
In the left-hand menu, click on **IAM users**, and then click the **Create user** button. Enter a descriptive name for the user (e.g., `lumi-migration-user`) and click **Next**.
   
### 3. Assign Permissions
- Choose **Add user to group**.
- If you don't have a group yet, click **Create group**. 
- Search for `AmazonS3FullAccess`, and tick it. This lets the user read and write S3 and nothing else, which is all these credentials are used for.
- Click **Create user group**, tick the newly created group, and click **Next**.
- Finally, click **Create user**.

### 4. Generate Access Keys
- On the success screen (green pop-up), click **View user**.
- Navigate to the **Security credentials** tab.
- Scroll down to the **Access keys** section and click **Create access key**.
- Select **Third-party service**, tick the confirmation box, and click **Next**.
- Give a name to the key and click **Create access key**.

> [!warning]
> **Safely store your credentials!**
> Be sure to save the **Access key** and **Secret access key** in a secure place. You will be prompted to enter these credentials when configuring `s3cmd` on LUMI in the next step.

> [!tip] Delete the key when you're done
> These access keys are long-lived: they stay valid until you remove them. Once your data is in S3 and you no longer need to run `s3cmd`, go back to the user's **Security credentials** tab and delete the access key. You can always create a new one if you need to transfer more data later.

## Create an S3 bucket

Your model weights and datasets need a bucket to land in. Open the AWS Console% and search for **S3**.

- In the **top-right corner**, next to your username, set your region, for example Stockholm (`eu-north-1`): the bucket lands in whichever region is shown there. Pick the region you will run your GPU machine in (this avoids paying to move data between regions) and note it down, as you enter it again when configuring `s3cmd`. 
- Click **Create bucket**.
- **Bucket name**: choose a name (e.g. `my-lumi-models`). This must be globally unique across all of AWS, so if the name is taken, pick another.
- Leave **Bucket namespace** on **Global namespace**, leave the remaining settings at their defaults, and click **Create bucket**.

You now have an empty bucket ready to receive your files.

## Transferring data with `rclone`

S3 (Simple Storage Service) is AWS's object storage service, and you copy your files into your bucket from LUMI with a command-line tool. We recommend `rclone`%: it is pre-installed on LUMI as part of the `lumio` module and is well suited to large model uploads, transferring files in parallel, showing live progress, verifying with checksums, and resuming cleanly if interrupted.

### 1. Load the required module

Log in to LUMI and load the module that provides `rclone`:

```bash
module load lumio
```

### 2. Configure an AWS remote

`rclone` reaches a cloud service through a named **remote**. Create one for AWS with the configuration wizard:

```bash
rclone config
```

Choose **n** for a new remote, then answer the prompts:

- **name**: `AWS`. You use this name in the upload command, and it is case-sensitive.
- **Storage**: choose `s3` (Amazon S3 Compliant Storage Providers).
- **provider**: choose `AWS`.
- **env_auth**: choose `false` (you enter the credentials yourself in the next step).
- **access_key_id**: paste the Access Key you created during the IAM setup.
- **secret_access_key**: paste the Secret Key.
- **region**: choose `eu-north-1` (Stockholm), matching your bucket.
- **endpoint**: leave empty.
- **location_constraint**: choose `eu-north-1`, matching the region.
- **acl**: leave empty. New buckets have ACLs disabled, so sending one causes an `AccessControlListNotSupported` error; leaving it empty keeps objects private by default.
- **Everything after** (encryption, KMS key, storage class, object lock): leave empty. S3 encrypts data at rest automatically.
- **Edit advanced config?**: `n`, then confirm with `y` and quit with `q`.

Confirm the remote exists:

```bash
rclone listremotes
```

This should print `AWS:`.

### 3. Upload your data

Copy your model folder from LUMI's Lustre filesystem into the bucket:

```bash
rclone copy LOCAL_DIR AWS:BUCKET_NAME/FOLDER -P
```

- `LOCAL_DIR`: the folder on LUMI containing your model (config, `*.safetensors`, tokenizer).
- `AWS:`: the remote name from `rclone config`, followed by a colon. It is case-sensitive, so `aws:` fails with `didn't find section in config file`.
- `BUCKET_NAME/FOLDER`: your bucket, then the folder to create inside it for this model.
- `-P`: show live transfer progress.

For example, `rclone copy Resnet-50 AWS:my-lumi-models/Resnet-50 -P` uploads the contents of `Resnet-50` into an `s3://my-lumi-models/Resnet-50/` folder.

> [!WARNING] Name the destination folder
> `rclone copy` uploads the *contents* of `LOCAL_DIR`, not the folder itself. If you leave the folder off the destination (`rclone copy Resnet-50 AWS:my-lumi-models`), the files land loose at the bucket root. Always name the destination folder so your weights end up in one clean folder, which is what the serving step points at later.

> [!TIP]
> `rclone copy` only adds and updates files; it never deletes anything already in the bucket. If you want the bucket to mirror your local folder exactly (removing files you have deleted locally), use `rclone sync` instead, but carefully, as it deletes.

## Transferring data with `s3cmd` (alternative)

`s3cmd`% does the same job as `rclone` and is also pre-installed on LUMI through the `lumio` module. Use it if you already know it or prefer it.

### 1. Load the required module

Log in to LUMI, and load the module that contains `s3cmd`:

```bash
module load lumio
```

### 2. Configure `s3cmd`

Run the configuration wizard to link the tool with your AWS account:

```bash
s3cmd --configure
```

You will be presented with a series of prompts. Answer them as follows:

- **Access Key**: Paste the Access Key you generated during the IAM setup.
- **Secret Key**: Paste the Secret Key.
- **Default Region**: Enter the region code where your bucket is located (e.g., `eu-north-1` for EU North).
- **S3 Endpoint**: Press **Enter** to accept the default `[s3.amazonaws.com]`.
- **DNS-style bucket+hostname:port template**: Paste the name of your target bucket followed immediately by `.s3.amazonaws.com`. For example: `my-lumi-models.s3.amazonaws.com`.
- **Encryption password**: Press **Enter** to skip (no password needed).
- **Path to GPG program**: Press **Enter** to skip.
- **Use HTTPS protocol [Yes]**: Type `Yes` and press **Enter**.
- **HTTP Proxy server name**: Press **Enter** to skip.
- **Test access with supplied credentials?**: Type `Y`. 
  *(You should see a success message indicating the connection worked fine.)*
- **Save settings?**: Type `y` to save the configuration. *(Note: This might take a minute or two.)*

### 3. Upload your data

You can now synchronise a directory from LUMI's Lustre filesystem to the S3 bucket you created. 

```bash
s3cmd sync LOCAL_DIR s3://BUCKET_NAME/PREFIX
```

- `LOCAL_DIR`: the folder on LUMI containing your model (config, `*.safetensors`, tokenizer).
- `BUCKET_NAME`: the exact name of your bucket.
- `PREFIX`: the folder inside the bucket for this model. With `s3cmd` you should always set one, without it your files land loose at the bucket root. A prefix (e.g. `Qwen2.5`) keeps your weights in one clean folder, which is what the serving step points at later.

> [!note]
> The command will appear to hang for a few minutes while it indexes the files, after which the upload progress will begin.

> [!tip]
> To view all available `s3cmd` commands, simply run `s3cmd` without any arguments. Note that not all commands may work on the LUMI installation.
