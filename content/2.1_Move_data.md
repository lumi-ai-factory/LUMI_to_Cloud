# Moving data to Google Cloud

To move your datasets and model weights from LUMI to a Google Cloud Storage bucket, you first need to configure the Google Cloud CLI% and authenticate.

## Google Cloud CLI Setup

1. **Navigate to your `$HOME` directory**
   
   Before you begin, navigate to your `$HOME`% directory on LUMI's login node. It is highly recommended to install the Google Cloud CLI here rather than in a shared project folder like `/scratch` or `/project`. Installing in a shared folder could allow other project members to modify the CLI binaries or its bundled Python environment, posing a security risk.
   
   ```bash
   cd ~
   ```

2. **Download and install Google Cloud CLI**
   
   Download the latest CLI package, extract it, and run the installation script. Extracting the archive may take a minute or two.
   
   ```bash
   curl -O https://dl.google.com/dl/cloudsdk/channels/rapid/downloads/google-cloud-cli-linux-x86_64.tar.gz
   tar -xf google-cloud-cli-linux-x86_64.tar.gz
   ./google-cloud-sdk/install.sh --usage-reporting=false --path-update=false --command-completion=false
   ```

## Transferring data with `gcloud`

Once the Google Cloud CLI% is installed, you are ready toauthenticate and move your datasets or model weights.

1. **Authenticate**
   
   Whenever you need to use `gcloud`% in the future, you must temporarily add it to your path by manually sourcing% the configuration file before running commands.
   
   Add `gcloud` to your path temporarily (adjust the path if installed elsewhere):
   
   ```bash
   source ~/google-cloud-sdk/path.bash.inc
   ```
   
   There are two ways to authenticate with Google Cloud: temporary and permanent.
   
   **Option A: Temporary Authentication (Recommended)**
   
   This method generates a short-lived authentication token that expires automatically (by default, after 1 hour). It requires you to have the Google Cloud CLI installed and authenticated on your own local machine.
   
   On your local machine (e.g., your laptop), first ensure you are logged in, and then generate the temporary access token:
   
   ```bash
   # On your laptop
   gcloud auth login  # Run this if you aren't already authenticated locally and follow the steps
   gcloud auth print-access-token
   ```
   
   Then, securely input the generated token as an environment variable on LUMI (this prevents the token from being saved in your shell history):
   
   ```bash
   # On LUMI
   read -rp 'Access token: ' CLOUDSDK_AUTH_ACCESS_TOKEN && export CLOUDSDK_AUTH_ACCESS_TOKEN
   ```

   <details>
   <summary>**Option B: Permanent Authentication**</summary>
   
   This method uses your personal Google account, meaning it grants the CLI your *entire Google Cloud identity*. It stores your permanent token in your user `$HOME` directory on LUMI (by default, in `~/.config/gcloud`). Even if you installed the Google Cloud CLI in a shared project folder like `/scratch`, your credentials remain private to your user account. While your configuration file is protected by strict file permissions and LUMI's security team watching out for vulnerabilities, we still recommend using a temporary token (Option A) or a scoped **Service Account** to minimise the blast radius.
   
   *(Note: If you need permanent access but want to restrict permissions—such as only allowing write access to a single bucket—you should create a Google Cloud Service Account and authenticate with a JSON key file instead of using your personal identity.)*
   
   To authenticate permanently, follow the on-screen steps after running:
   
   ```bash
   gcloud init
   ```
   
   **Clean up:** Once you have finished transferring your files and you don't need to access Google Cloud, you can easily revoke access to remove your credentials from LUMI:
   
   ```bash
   gcloud auth revoke --all
   ```

   </details>
   
   > [!tip]
   > The Google Cloud SDK creates tens of thousands of small files during installation, which stresses the Lustre file system and consumes a large portion of your `$HOME` file count quota of 100k files. We strongly recommend deleting the `google-cloud-sdk` directory entirely when you no longer need it.

2. **Transfer your files**
   
   You can now copy files and directories using the `gcloud storage cp` command.
   
   ```bash
   # Example Download (from Google Cloud to LUMI):
   gcloud storage cp gs://YOUR_BUCKET_NAME/FILE_NAME .
   
   # Example Upload (from LUMI to Google Cloud):
   gcloud storage cp FILE_NAME gs://YOUR_BUCKET_NAME/
   ```
