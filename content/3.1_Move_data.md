# Moving data to Azure

To move your datasets and model weights from LUMI to an AWS S3 bucket, you create IAM access keys, make an S3 bucket, and then upload to it with a command-line tool (we recommend `rclone`; `s3cmd` is an alternative).


To move your datasets and model weights from LUMI to Azure storage, you need Azure subscription account, create a storage account, create a container to store your data and then upload to the container with command-line tool. This guide will focus on using Azure access key to connect and transfer data through `rclone`. 


## Set up requirements
Along with the prerequisites in [Azure overview page](3_Azure.md), you will need to set up the Azure storage account in [Azure Portal](https://portal.azure.com/). Azure Portal will be where you can set up your Azure Storage account for the Blob storage and where you set up your VMs if you choose this route. 

### Creating storage account 
To create a storage account, select `Create a resource` in Azure Portal front page and then select `Storage Account`.  The storage account can be customized based on the user's intention on different aspects such as Networking, Security or Encryption. In this guide, we will focus on the most basic set up with sufficient security to enable the data transfering from LUMI and connecting it to Azure VMs or Azure Machine Learning workspace. 


In the `Create a storage account`section, you will see such sections like below: 
**Basics**
- Subscription: Select the corresponding subscription you have subscribed for this project.
    - Resource group: The name of your resource group.

- Storage account name: the name of your choice.
- Region: for Finland, select `(Europe) Sweden Central`.
- Primary service: Azure Blob Storage or Azure Data lake Storage
- Performance: Standard 
- Redundancy: choose the option that is best suited for your company or project

**Advanced**
- Access tier: choose the option that is best suited for your company or project. In this guide, we will choose `Hot`. 

**Networking**
- Public network access: Enable
- Public network access scope: Enablae from all networks. In practical case, you should choose Enable from selected virtual networks and IP addresses for better secured network. In this guide, we will use Enable from all networks for simplicity. 

For more information on how to customize your storage account, you can visit Microsoft official guide on [Create an Azure storage account](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create?tabs=azure-portal)

### Creating container under storage account 
After creating the storage account, select the storage account name from the front page of Portal Azure to see further information. On your left, under the section Security + networking, you will find the section **Access keys**. Access keys will include 2 keys you can use for connection to the storage account. We will assume the default of using key 1 right now. 

- To secure the key, click on **Access keys** section and find key 1.
- Copy key 1 to somewhere safe and private, preferably local to your usage. 

Next, we will go to section Data storage and go to **Containers**.

- To create a container, click on the **+** sign to create and choose your own name for the container. 

After creating the container, right click on the it to generate the SAS Url. 
- Signing method: it is recommended by Microsoft that user uses User delegation key. For single person usage, Account key is still sufficient and simple as you can get access to not just blob but also queue, table and file services.
- Permission: Choose at least **Read** and **Write**. You can choose other permission rights depending on your usage. 
- Allowed IP Addresses: leave blank. 
- Allowed protocols: HTTPS only. 
- Select the time period of your choice. 
- Copy and save the SAS Url somewhere safe like the Access key. 

## Transferring data with `rclone`
After creating and generating SAS url, we can now set up and start the transfering process. In this guide, we recommend using `rclone` to transfer data. You will copy your files into the Azure container from LUMI with `rclone`command-line tool. `rclone` is pre-installed on LUMI as part of the `lumio` module and is well suited to large model uploads, transferring files in parallel, showing live progress, verifying with checksums, and resuming cleanly if interrupted.


### 1. Load the required module
Log in to LUMI in terminal and load the module that provides `rclone`:

```bash
module load lumio
```

### 2. Configure an Azure remote

`rclone` reaches a cloud service through a named **remote**. Create one for Azure with the configuration wizard:

```bash
rclone config
```

Then answer to the prompt: 
- **remote**: **n** for new remote
- **name**: AZURE 
- **storage**: option 40 - Azure storage Accound name
- **acount**: the Azure Storage Account name you have created.
- **env_auth**: false
- **key**: Your Access key 1 that has been saved. 
- **sas_url**: Your SAS Url under the container that has been saved.
Leave all other options empty until you reach 
- **Keep this "NAME OF REMOTE" remote?**: Yes

**q** to quite the configuration. 

```bash
rclone listremotes
```
You will see `AZURE:` as one of the remote we have created.
